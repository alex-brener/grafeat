# Instagram First-Party App Capability vs. Third-Party Platform API Capability (Mentions, Tags, Hashtags, Notifications)

## Does Instagram's Help Center document notification history / how far back you can see past mentions or tags in the app?

### Takeaway
Instagram's Help Center documents *that* mentions and tags generate notifications in the Activity/"You" feed and documents the *controls* around tagging visibility (manual vs. automatic approval), but no official Help Center page found in this research states a specific retention window (e.g., "X days") for how far back the Activity/notifications feed can be scrolled. Claims of a fixed "3 days" limit found in secondary sources are not from Instagram itself and should be treated as unverified.

### Cited Findings
- When you mention someone, they get a notification in their Activity feed; this applies to mentions in captions and in comments — [Instagram Help Center: Mentions](https://help.instagram.com/1558367297777457)
- Reply to someone in a comment thread by mentioning them; they get a notification in their Activity feed to view the comment — [Instagram Help Center: Mentions](https://help.instagram.com/1558367297777457)
- If an account with a private profile mentions someone who isn't an approved follower, the mentioned person does not get a notification in the "You" section of Activity and does not get a push notification — [Instagram Help Center: Mentions](https://help.instagram.com/1558367297777457)
- You can choose whether photos/videos you're tagged in appear on your profile automatically or manually; with manual approval on, you still get a notification every time someone tags you, but the tag doesn't appear on your profile (in Photos of You) until you approve it — [Instagram Help Center: Choose to manually approve posts you're tagged in](https://help.instagram.com/496738090375985)
- To manage this, go to profile → Settings → Privacy and Security → Photos and Videos of You → toggle "Add Automatically" — [Instagram Help Center: Choose to manually approve posts you're tagged in](https://help.instagram.com/496738090375985)
- Instagram does not send a notification when you hide a tagged post from your profile — [Instagram Help Center (via search index)](https://help.instagram.com/496738090375985)
- A secondary (non-Instagram) source claims in-app push notification history/drawer only reliably shows roughly the last 3 days, with anything older requiring OS-level notification history (e.g., Android 11+ "Notification History") or third-party tools — this is **not sourced to Instagram's own documentation** and could not be corroborated against an official page — [remote.tools blog](https://www.remote.tools/instagram/see-old-instagram-notifications)

### Inferences
- Instagram's own app treats "Activity"/notifications as a live feed rather than a documented, bounded archive — the Help Center describes behavior and settings but is silent on data retention/lookback duration, which suggests this was never published as a product guarantee (unlike, say, the documented "Watch History: last 30 days" feature for Reels).
- Because retention isn't officially documented, any Challenge Curator design that assumes an organizer can "look back N days" in their own Activity tab to self-serve-discover missed mentions is relying on undocumented, possibly account/version-dependent behavior, not a stable contract.

### Gaps
- No official Instagram Help Center statement was found specifying exactly how many days/weeks of past mentions or tags remain visible/scrollable in the Activity ("You") tab. This should be treated as an open question — only secondary/unofficial sources (not corroborated) offered a specific number (3 days), and that figure referred to the OS notification drawer, not the in-app Activity history, so it may not even be the right metric.
- Whether the Activity tab's own mention/tag history (distinct from push notifications) has a longer or unlimited lookback was not confirmed either way by any source found.

## Does Instagram deliberately withhold certain first-party discovery capabilities from the third-party API as a policy choice (vs. an access-level/review gate)?

### Takeaway
There is clear structural/documented evidence of a capability gap (mentions require webhook-sourced IDs rather than being bulk-listable; hashtag API is time- and quota-boxed; Tag People has no webhook at all), but no source found in this research explicitly frames this as a stated Meta *policy rationale* ("we withhold X on purpose") — the gap is demonstrated by what the docs do and don't offer, not by an explicit Meta statement of intent. This distinction should be treated as an inference, not a documented admission.

### Cited Findings
- The Instagram Platform mentions workflow requires first subscribing to the webhook `mentions` field, then parsing the webhook payload to obtain `media_id`/`comment_id`, then querying `GET /{ig-user-id}?fields=mentioned_media.media_id({media_id})` or `mentioned_comment` with that specific ID — there is no documented way to retrieve a full list of "all mentions of my account" by a bulk/listing call without already holding a specific ID from a webhook event — [Meta for Developers: Mentions](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/mentions/); corroborated by multiple independent secondary technical write-ups describing the same required `media_id`/`comment_id` parameter and webhook-first workflow — [elfsight.com Instagram Graph API guide](https://elfsight.com/blog/instagram-graph-api-complete-developer-guide-for-2026/), [wpsocialninja.com Instagram Graph API guide](https://wpsocialninja.com/instagram-graph-api/)
- Mentions on Stories are not supported by the API at all — [Meta for Developers: Mentions](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/mentions/)
- Webhooks will not be sent if the media the comment/@mention appears on was created by an account set to private — [Meta for Developers: Mentions](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/mentions/)
- By contrast, `GET /{ig-user-id}/tags` ("Tags") is documented as a true listable edge — "a collection of IG Media objects in which an IG User has been tagged by another Instagram user" — retrievable directly without needing a webhook-supplied ID first — [Meta for Developers: Tags](https://developers.facebook.com/docs/instagram-api/reference/ig-user/tags)
- The official Instagram webhooks reference for the Instagram product lists supported fields as: `comments`, `live_comments`, `messages`, `message_edit`, `message_reactions`, `mentions`, `messaging_handover`, `messaging_referral`, `messaging_seen`, `messaging_postbacks`, `standby`, `story_insights` — there is no `tags` webhook field, meaning native "Tag People" tagging events have no real-time push notification path for third-party apps at all; the only way to discover them via API is to poll `/tags` — [Meta for Developers: Webhooks Reference: Instagram](https://developers.facebook.com/docs/graph-api/webhooks/reference/instagram)
- `GET /ig_hashtag_search` hashtag queries are capped at 30 unique hashtags per Instagram Business/Creator account in a rolling 7-day window, after which previously-queried hashtags "reset" — [Meta for Developers docs, as summarized across secondary sources](https://developers.facebook.com/docs/instagram-api/reference/hashtag/recent-media); corroborated by [bulkit.io Instagram Search API guide](https://bulkit.io/blog/instagram-search-api) and [help.nosto.com FAQ](https://help.nosto.com/en/articles/8896595-faq-what-are-the-limits-of-instagram-hashtag-search-terms)
- The hashtag `recent_media` edge "only returns media objects published within 24 hours of query execution," is paginated at a max of 50 results/page, and only returns public media — [Meta for Developers: Recent Media](https://developers.facebook.com/docs/instagram-api/reference/hashtag/recent-media) (official URL confirmed via search snippet; direct fetch returned 404, likely due to a docs reorganization/JS rendering — treat as corroborated-but-not-directly-verified)
- The Instagram API (Business Discovery, Hashtag Search) only works for/returns Business and Creator accounts; personal accounts are categorically outside the API's reach since Meta shut down the Instagram Basic Display API (the only path that touched personal accounts) on December 4, 2024 — [TechCrunch: Instagram locks out developers of third-party consumer apps](https://techcrunch.com/2024/12/06/instagram-locks-out-developers-of-third-party-consumer-apps); summarized in [zernio.com Instagram API 2026 guide](https://zernio.com/blog/instagram-api)
- One technical commentary explicitly frames this as deliberate design rather than incidental gap: "professional accounts receive access to a limited, permissioned surface that still operates under quotas, time windows, endpoint rules, and versioned platform policies... neither [top_media nor recent_media] should be presented as a complete global archive" — [zernio.com: Instagram Graph API 2026: Dev Questions Meta's Docs Leave Open](https://zernio.com/blog/instagram-graph-api) — note this is third-party commentary/interpretation, not a direct Meta policy statement.

### Inferences
- The asymmetry between `/tags` (bulk-listable, no webhook required) and `mentioned_media`/`mentioned_comment` (ID-lookup only, webhook-dependent) is a structural fact visible in the official docs themselves, not merely an access-tier restriction — even a fully-reviewed, Advanced-Access app cannot "list all mentions of my account" the way it can "list all tags of my account." This is strong circumstantial evidence of an intentional design choice to prevent mention-discovery from being a standing bulk/search capability, though no Meta source states this motive explicitly.
- Similarly, the complete absence of a `tags` webhook field (vs. the existence of a `mentions` webhook field) means native Tag People events have no real-time push path for developers at all — only polling. Combined with the hashtag API's 24-hour recency window and 30-hashtags/week quota (both quota/time-boxed in ways the first-party in-app hashtag browse experience is not), the pattern across all three features (mentions, tags, hashtags) consistently favors the first-party app's unrestricted real-time/historical access over any third-party-replicable capability.
- Because personal (non-Business/Creator) accounts are excluded from hashtag search and Business Discovery entirely, a hashtag-based challenge that draws submissions from personal accounts (very plausible for a casual photo challenge like `#callivember2026`) may be structurally invisible to the API regardless of quota — this is a separate, likely more consequential, gap than the recency window.

### Gaps
- No Meta source was found that explicitly states "we intentionally withhold full mention/tag search from third parties for policy reason X (e.g., privacy, spam prevention, platform control)." The gap is demonstrated behaviorally by the docs, not asserted as policy. Treat the "deliberate withholding" framing as a well-supported inference, not a confirmed Meta statement.
- No developer-community discussion thread (e.g., Meta's own developer community forum, Stack Overflow) was directly fetched in this pass specifically debating "why can't I bulk-list mentions" — only secondary blog summaries. A deeper pass through Meta's developer community forum directly could strengthen this with direct developer complaints/Meta staff responses, but was out of scope given the ~15-tool-call budget for this research track.

## Does the Instagram app's own hashtag search/browse show results beyond what `recent_media`'s ~24-hour window suggests?

### Takeaway
Yes — the in-app hashtag page's "Top" tab is not time-boxed at all (it surfaces high-engagement posts regardless of age) and the "Recent" tab shows reverse-chronological posts with no stated cutoff, so the first-party experience is materially broader than the API's `recent_media` edge, which is hard-capped at media published in the last 24 hours. This confirms the Graph API hashtag surface is a narrow, quota- and time-boxed subset of what a human sees browsing the same hashtag in-app.

### Cited Findings
- On a hashtag page, a "Top Posts" section appears above "Most Recent"; Top Posts are not described as time-limited and are selected by engagement/relevance signals rather than recency — [Instagram Help Center: Hashtag Pages](https://help.instagram.com/466210366861501) (content as reflected in search index/secondary summary; direct fetch of help.instagram.com pages was blocked by client-side rendering in this research pass — see note below)
- The "Most Recent" section shows photos/videos "in the order that they were posted," i.e., reverse chronological with no documented cutoff — [Instagram Help Center: Hashtag Pages](https://help.instagram.com/466210366861501)
- Instagram has, at various points, made changes to how the Recent tab on hashtag pages is surfaced (e.g., reporting around removal/restoration of a dedicated "Recent" tab in some contexts) — [TechCrunch: Instagram removes recent tab from hashtag pages](https://techcrunch.com/2022/04/19/instagram-removes-recent-tab-hashtag-pages/amp/) — included for context that the in-app hashtag UI has changed over time and should be reverified at implementation time, not taken as a permanent UI contract.
- By contrast, the official API's `recent_media` edge for a hashtag "only returns media objects published within 24 hours of query execution" — [Meta for Developers: Recent Media](https://developers.facebook.com/docs/instagram-api/reference/hashtag/recent-media), consistently corroborated across secondary developer guides — [elfsight.com](https://elfsight.com/blog/instagram-graph-api-complete-developer-guide-for-2026/), [bulkit.io](https://bulkit.io/blog/instagram-search-api)
- Instagram's general text/hashtag search ranks results using signals including the literal text match against usernames/bios/captions/hashtags/places, the searching user's own activity/follow graph, and popularity signals (clicks, likes, shares, follows) for the result — i.e., personalized and engagement-weighted, not a neutral/complete index — [Instagram (about.instagram.com): Breaking Down How Instagram Search Works](https://about.instagram.com/blog/announcements/break-down-how-instagram-search-works)

### Inferences
- Because `recent_media` is capped at a 24-hour-old window and polling is additionally capped at 30 unique hashtags/week per account, a Challenge Curator product relying purely on this API edge would miss any submission posted more than ~24 hours before a given poll cycle unless it polls very frequently and never misses a window — functionally, the API cannot reconstruct the full history of a hashtag the way a human scrolling the in-app hashtag page can (the human can scroll back through "Recent" indefinitely, constrained only by Instagram's own feed-loading UX, not a hard 24-hour rule).
- `top_media` is not time-boxed the same way, but it is engagement-ranked rather than exhaustive, so it is also not a substitute for "all posts using this hashtag" — a challenge submission with low engagement could be excluded from `top_media` the same way it might not surface in a human's casual Top-tab browse, but a human can switch to Recent to find it chronologically; the API's `recent_media`, being time-gated, cannot play that same fallback role once 24 hours have passed.

### Gaps
- Direct WebFetch retrieval of the raw help.instagram.com "Hashtag Pages" article text failed in this research pass (the page returned only a client-side-rendered "Help Center" shell with no body text extractable via the fetch tool used); the Hashtag Pages content above is reconstructed from search-engine snippet summaries that appear to paraphrase/quote the Help Center page, not from a direct fetch of the full article. This should be re-verified by a human or a browser-capable tool if higher confidence is needed on exact Help Center wording.
- The exact current (October 2026) state of hashtag page tabs (whether "Recent" is present as a separate tab or merged/removed in some surfaces, following Instagram's periodic UI changes referenced by TechCrunch) was not independently reverified against the live app; treat the Top/Recent description as directionally correct but potentially stale on exact tab naming/presence.

## Summary table: first-party capability vs. closest third-party API equivalent

### Takeaway
Of the seven human workflows in scope, two (notification on native Tag People tagging, and the "Tagged/Photos of You" viewing surface) have a genuine bulk/listable API analog (`/tags`); the two mention-notification workflows (caption and comment @mentions) have only a narrow, non-bulk, webhook-ID-dependent analog; hashtag search/browse has an analog that is quota- and time-boxed far below the in-app experience; and general Instagram search plus notification-history-browsing have **no third-party API equivalent at all** — these are the clearest first-party-only capabilities found in this research.

### Cited Findings
- Receiving a notification when @mentioned in a **caption**: first-party generates an Activity notification — [Instagram Help Center: Mentions](https://help.instagram.com/1558367297777457). Closest API equivalent: webhook `mentions` field fires, then `GET /{ig-user-id}?fields=mentioned_media.media_id({media_id})` fetches that specific media — requires the ID from the webhook; no bulk "list all caption mentions" call exists — [Meta for Developers: Mentions](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/mentions/)
- Receiving a notification when @mentioned in a **comment**: same Activity-feed behavior — [Instagram Help Center: Mentions](https://help.instagram.com/1558367297777457). API equivalent: webhook `mentions` field → `GET /{ig-user-id}?fields=mentioned_comment.comment_id({comment_id})`, same ID-dependency caveat, and explicitly excluded if the commenting account is private or if the mention is on a Story — [Meta for Developers: Mentions](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/mentions/)
- Receiving a notification for native **Tag People** tagging: first-party notifies and offers manual-approval workflow before the tag shows under Photos of You — [Instagram Help Center: Choose to manually approve posts you're tagged in](https://help.instagram.com/496738090375985). API equivalent: **no webhook field exists for tags at all** (confirmed absent from the official Instagram webhooks field list) — [Meta for Developers: Webhooks Reference: Instagram](https://developers.facebook.com/docs/graph-api/webhooks/reference/instagram); only a pollable `GET /{ig-user-id}/tags` edge exists, so real-time notification parity is not achievable via API, only delayed polling.
- Viewing **Tagged/Photos of You**: first-party profile tab, with automatic or manually-approved entries — [Instagram Help Center: Choose to manually approve posts you're tagged in](https://help.instagram.com/496738090375985). API equivalent: `GET /{ig-user-id}/tags` — a genuine bulk-listable edge, the closest 1:1 match of any capability examined — [Meta for Developers: Tags](https://developers.facebook.com/docs/instagram-api/reference/ig-user/tags) — though it excludes private media and reflects only what's tagged, not approval-queue state.
- Searching/browsing a **hashtag** in-app (Top + Recent, no documented time cutoff): [Instagram Help Center: Hashtag Pages](https://help.instagram.com/466210366861501). API equivalent: `ig_hashtag_search` → `top_media`/`recent_media`, but `recent_media` is capped at a 24-hour window, both are capped at 30 unique hashtags/account/7-day rolling window, and only Business/Creator-account public media is returned (personal accounts excluded) — [Meta for Developers: Recent Media](https://developers.facebook.com/docs/instagram-api/reference/hashtag/recent-media); [TechCrunch on Basic Display API shutdown](https://techcrunch.com/2024/12/06/instagram-locks-out-developers-of-third-party-consumer-apps)
- Using Instagram's **general search** for text/hashtag discovery, personalized/engagement-ranked — [about.instagram.com: Breaking Down How Instagram Search Works](https://about.instagram.com/blog/announcements/break-down-how-instagram-search-works). **No third-party API equivalent was found for this at all** — the Graph/Instagram Platform API exposes no general free-text search across arbitrary posts/captions; the only search-like primitive is the hashtag-ID lookup (`ig_hashtag_search`) feeding into the time/quota-boxed media edges above, not a general query surface.
- **Activity/notification history** of past mentions and tags: first-party has an Activity ("You") tab; no official retention duration documented (see first key question above). **No third-party API equivalent exists** — there is no endpoint to retrieve a user's own historical notification log; developers must have been subscribed to webhooks at the time of the event, or use the narrow `/tags` and ID-driven mention edges going forward — there is no way to retroactively pull "everything that happened before I integrated."

### Inferences
- The single clearest, best-evidenced "first-party only, no API path at all" capabilities are: (1) Instagram's general free-text/hashtag search feature, and (2) retroactive notification/activity history for mentions and tags predating a developer's webhook subscription. Both are absent from the API by omission (no corresponding endpoint found in Meta's own reference docs across this and the parallel API-detail research track), not merely rate-limited or scoped-down.
- For a product like Challenge Curator, this implies: hashtag-based discovery via API will systematically under-count personal-account submissions and anything older than ~24 hours per poll cycle; mention-based discovery via API can only work prospectively from the moment webhooks are configured (no backfill of pre-existing mentions) and only for mentions on non-private accounts' captions/comments (not Stories); and tag-based discovery via `/tags` is the one area where API parity with the human "Photos of You" experience is closest to achievable, modulo private-media exclusion.

### Gaps
- This track did not re-verify the full permission/App Review requirements for each endpoint (e.g., `instagram_business_manage_comments`) — that is explicitly covered by a parallel research track per the assignment's constraints.
- Whether Instagram's general search has ever exposed any programmatic form (even a deprecated/legacy one, e.g., old Instagram API v1 search endpoints pre-2018) was not investigated here, as the assignment scope is 2026 "official" Instagram Platform API; any such legacy capability would in any case now be shut down per the Basic Display API deprecation already cited.
