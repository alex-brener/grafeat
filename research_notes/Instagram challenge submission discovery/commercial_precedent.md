# Commercial Precedent: How Current (2026) Products Auto-Collect Instagram UGC by Hashtag/@Mention

Scope note: this covers the products in the assigned priority order. For every claim, I've marked whether it is a **DOCUMENTED FACT** (vendor's own stated claim, or independently verifiable) or a **LIKELY ARCHITECTURE/HYPOTHESIS** (my inference from Meta's known API constraints). Vendor marketing claims are reported as "vendor claims X" — they are documented facts about *what the vendor says*, not independently verified proof that the mechanism is what the vendor says it is.

## 1. Easypromos — "Mention + Hashtag" / "Instagram Contest with Hashtag"

### Takeaway
Easypromos is the clearest documented case: participants must post to their main feed (not Stories) with **both** an @mention of the organizer's account **and** the campaign hashtag present at time of posting, from a **public** account (personal accounts are explicitly said to be acceptable for participants). The organizer-side requirements are inconsistently described across Easypromos's own pages — the marketing landing page implies no special organizer account is needed, but the help-center tutorial says the organizer must use an Instagram **business account** connected to the Facebook Page that manages it. Easypromos states it uses "Meta's official API" and claims annual Meta verification, but does not publicly disclose the exact Advanced-Access/App-Review mechanism; the help center explicitly states the Instagram API does not allow retroactive search, so collection is forward-looking/real-time only, with no historical backfill.

### Cited Findings
- DOCUMENTED FACT (vendor claim) — Participants post photos, videos, or Reels to Instagram with a mention of the brand plus the campaign hashtag; "the system automatically imports participants with public profiles... without requiring users to register" — [Easypromos Mention & Hashtag Contest](https://www.easypromosapp.com/instagram-contest-with-hashtag/)
- DOCUMENTED FACT (vendor claim) — "a real-time Instagram mention monitor... detects whenever a user with a public Instagram profile posts on Instagram and mentions the brand, and if the post includes the contest hashtag, it is automatically imported" — [Easypromos Mention & Hashtag Contest](https://www.easypromosapp.com/instagram-contest-with-hashtag/)
- DOCUMENTED FACT (vendor claim) — "Easypromos uses Meta's official API to import all content from participating posts automatically, and Meta verifies Easypromos for legal compliance annually" — [Easypromos Mention & Hashtag Contest](https://www.easypromosapp.com/instagram-contest-with-hashtag/)
- DOCUMENTED FACT (vendor claim) — Up to 3 hashtags can be configured; a post qualifies if it contains at least one of them — [Easypromos Mention & Hashtag Contest](https://www.easypromosapp.com/instagram-contest-with-hashtag/); [Tutorial: How to create a Mention+Hashtag contest](https://soporte.easypromosapp.com/hc/en-us/articles/28758765065108-Tutorial-How-to-create-a-Mention-Hashtag-contest)
- DOCUMENTED FACT (vendor claim) — Organizer must use "an Instagram business account" and "connect with the profile that manages the Facebook page linked to the Instagram account" — [Tutorial: How to create a Mention+Hashtag contest](https://soporte.easypromosapp.com/hc/en-us/articles/28758765065108-Tutorial-How-to-create-a-Mention-Hashtag-contest) — **this conflicts with** the main landing page, which documents no organizer account-type requirement at all; the help-center tutorial appears to be the more technically authoritative source.
- DOCUMENTED FACT (vendor claim) — Private participant profiles cannot be auto-imported; those users must submit manually via a contest web form with email/terms acceptance instead — [Tutorial: How to create a Mention+Hashtag contest](https://soporte.easypromosapp.com/hc/en-us/articles/28758765065108-Tutorial-How-to-create-a-Mention-Hashtag-contest); [Conditions for importing publications](https://soporte.easypromosapp.com/hc/en-us/articles/207886306-Conditions-for-importing-publications-in-the-Mention-Hashtag-Contest)
- DOCUMENTED FACT (vendor claim) — Stories do not count; only feed posts qualify — [Tutorial: How to create a Mention+Hashtag contest](https://soporte.easypromosapp.com/hc/en-us/articles/28758765065108-Tutorial-How-to-create-a-Mention-Hashtag-contest)
- DOCUMENTED FACT (vendor claim) — "Past posts are not imported into the contest" (no historical backfill) because "the Instagram API does not allow retroactive searches" — [Tutorial: How to create a Mention+Hashtag contest](https://soporte.easypromosapp.com/hc/en-us/articles/28758765065108-Tutorial-How-to-create-a-Mention-Hashtag-contest); [Conditions for importing publications](https://soporte.easypromosapp.com/hc/en-us/articles/207886306-Conditions-for-importing-publications-in-the-Mention-Hashtag-Contest)
- DOCUMENTED FACT (vendor claim) — If the mention and hashtag are added to the caption *after* initial publication (i.e., an edited caption), the post will not be detected/imported — "the comment of the Instagram post can't be edited later to add the mention and the hashtag of the contest" — [Conditions for importing publications](https://soporte.easypromosapp.com/hc/en-us/articles/207886306-Conditions-for-importing-publications-in-the-Mention-Hashtag-Contest)
- DOCUMENTED FACT (vendor claim) — Documented, enumerated reasons a qualifying post may fail to import: (1) private profile, (2) Instagram integration not enabled before launch, (3) post published outside the entry-period dates, (4) caption edited after posting to add tags, (5) videos cannot always be manually added due to "Meta API limitation" (only photos can be manually added as a fallback), (6) general Instagram/Meta API non-responsiveness — [Conditions for importing publications](https://soporte.easypromosapp.com/hc/en-us/articles/207886306-Conditions-for-importing-publications-in-the-Mention-Hashtag-Contest)
- DOCUMENTED FACT (vendor claim) — Elsewhere, Easypromos is described (per aggregated web content, not a primary Meta partner-directory confirmation) as holding "Meta Verified Tech Provider" status — [search aggregation, no single confirmed primary URL found]
- DOCUMENTED FACT — Meta's official `ig_hashtag_search` endpoint (the public Graph API mechanism closest to what a "hashtag discovery" feature would need) requires the `Instagram Public Content Access` feature, the `instagram_basic` permission, and a user access token from "Instagram API with Facebook Login"; it is rate-limited to 30 unique hashtags queried per 7-day period — [Meta for Developers: ig_hashtag_search reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-hashtag-search)

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — Given that Easypromos documents "real-time" detection, the inability to search retroactively, and a hard cap-like framing ("only new posts... detected upon initial publication"), the mechanism most consistent with Meta's actual public API surface is: each Easypromos customer (organizer) connects their own Instagram professional account (via Facebook Login) to Easypromos, Easypromos's own Meta app queries `ig_hashtag_search` and/or mention-related endpoints under that connected account's token, and Easypromos's shared app itself holds Advanced Access / Instagram Public Content Access approval from its own App Review (not a per-customer App Review) — i.e., Easypromos very plausibly operates one Meta app that has gone through Advanced Access, and each organizer's Facebook Page connection supplies the authorized "IG User" context the API requires. This would explain both: (a) why the organizer needs a business/professional account + Facebook Page (matches Meta's actual API prerequisites), and (b) why Easypromos can call itself "Meta verified" (consistent with holding an approved Business Verification + App Review app).
- LIKELY ARCHITECTURE/HYPOTHESIS — The "30 unique hashtags per 7 days" rate limit on `ig_hashtag_search` is a strong candidate explanation for Easypromos's own self-imposed limit of "up to 3 hashtags" per contest and for documented cases of "Instagram's API did not return those posts" — this reads as a plausible symptom of exactly this kind of Meta-side rate limiting/non-determinism, not proof of it.
- Cannot confirm from public sources whether Easypromos's "real-time mention monitor" is actually driven by a Meta webhook/subscription versus Easypromos polling the Graph API on an interval — the word "real-time" is vendor marketing language and no technical architecture diagram or webhook disclosure was found.

### Gaps
- No primary-source confirmation (e.g., Meta's own partner directory, or an Easypromos legal/security page with an explicit badge) of Easypromos's exact Meta access tier (Advanced Access vs. Standard Access) or of "Meta Verified Tech Provider" status specifically — this claim surfaced only via an AI-search synthesis, not a directly quotable vendor or Meta primary source URL, so it should be treated as unverified.
- Whether each Easypromos customer undergoes any individual Meta review step, or whether it is entirely Easypromos's single shared app's approval, could not be confirmed from public documentation — the help center's instructions to "connect with the profile that manages the Facebook Page" are consistent with either model.
- No explicit statement of whether native Instagram "Tag People" (as opposed to a text @mention in the caption) is supported, required, or irrelevant — all of Easypromos's own language refers only to caption/description mentions ("mentions the brand"), with no reference to the "Tag People" photo-tagging feature at all, suggesting caption @mention is the actual trigger and Tag People is not used/required — but this is inferred from absence, not a positive statement.

## 2. Mention.com — Instagram keyword/caption monitoring

### Takeaway
Public documentation on Mention.com's specific Instagram mechanism is very thin. Mention.com markets a "Media Monitoring API" and a "streaming API" claiming real-time social monitoring including Instagram, but no primary source was found describing the exact Instagram endpoint(s), access tier, or whether Instagram monitoring today relies on the official Graph API at all versus a different/degraded data path. Historically, broad 2018 Instagram API lockdowns (removing third-party access to public content, follower lists, and comments for non-owned accounts) would have materially constrained exactly this kind of tool, and no evidence was found that Mention.com disclosed how (or whether) it adapted its Instagram feature afterward.

### Cited Findings
- DOCUMENTED FACT (vendor claim) — Mention advertises a "Media Monitoring API" whose "real-time API gives you social media and web crawling capabilities" and states users "get mentions from Facebook, Twitter, Instagram, Pinterest, and LinkedIn," with a "streaming API" for live data — [Mention Media Monitoring API](https://mention.com/en/media-monitoring-api/)
- DOCUMENTED FACT — Instagram's April 2018 platform changes disabled several APIs used by third-party apps, and by December 11, 2018 third-party apps could no longer read public content via the older Instagram API; further restrictions on reading a user's own profile/media followed in early 2020 — [MacRumors: Instagram Disables Several APIs Used by Third-Party Apps](https://www.macrumors.com/2018/04/04/instagram-disables-third-party-app-apis/)
- No primary Mention.com help-center or developer page describing the exact Instagram capture mechanism (hashtag vs. caption @mention vs. keyword-in-bio, account-type requirements, real-time vs. polling, or backfill) could be located; the specific product page URL attempted (`mention.com/en/features/instagram-monitoring/`) returned a 404.

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — Given (a) the absence of any public Mention.com documentation describing Instagram-specific Graph API scopes, App Review status, or a "connect your Instagram Business account" onboarding step comparable to Easypromos/Woobox/ShortStack, and (b) the severity of Meta's 2018–2020 API lockdowns on third-party public-content access, it is plausible that Mention.com's Instagram "monitoring" today is materially reduced in scope compared to its original design, or depends on a different/degraded data-acquisition layer (e.g., a social-listening data reseller, web-level crawling of public posts, or a narrower official API surface limited to the customer's own connected account) rather than broad keyword/hashtag discovery across all public Instagram content. This is an inference, not a confirmed fact.

### Gaps
- The exact upstream mechanism for Mention.com's current Instagram monitoring capability (official Graph API vs. third-party data provider vs. web scraping) could not be established from public sources within this research pass. This should be flagged explicitly to the report writer as an open question — Mention.com's own marketing is vague ("mentions from... Instagram") and no technical/API documentation, help-center article, or independent review was found that specifies the mechanism, account requirements, or real-time/polling behavior.
- Whether caption @mention specifically (as opposed to brand-name keyword mentions in bios/captions generally) is a supported trigger could not be confirmed.

## 3. Woobox — Instagram hashtag/UGC collection for contests/galleries

### Takeaway
Woobox requires the organizer to have an Instagram **Business Profile connected to a Facebook Page** in order to pull hashtags at all. Collection is hashtag-based (not described as @mention-based), supports public participant accounts only, and is explicitly framed as a mix of a short lookback window plus ongoing collection — not pure real-time, and not full historical backfill.

### Cited Findings
- DOCUMENTED FACT (vendor claim) — "Instagram requires that you have a Business Profile connected to your Facebook page in order to pull hashtags from the platform" — [Woobox: Collecting submissions from Instagram](https://help.woobox.com/articles/collecting-submissions-from-instagram/) (per search-engine-cached summary; direct WebFetch of this page failed with a certificate error during this research pass, so treat as a secondary citation of the same page pending re-verification)
- DOCUMENTED FACT (vendor claim) — "Woobox will pull in any public uploads using your required hashtag(s) from the previous 24 hours and throughout the duration of your campaign's Entry period" — [Woobox: Collecting submissions from Instagram](https://help.woobox.com/articles/collecting-submissions-from-instagram/)
- DOCUMENTED FACT (vendor claim) — "Fans can enter by uploading to Instagram and including your required hashtag(s) in the caption (the entrant's profile must be public as well)" — [Woobox: Collecting submissions from Instagram](https://help.woobox.com/articles/collecting-submissions-from-instagram/)
- DOCUMENTED FACT (vendor claim) — Standard photo posts, Reels, and videos can all be imported via the required hashtag(s) and auto-published to the gallery if auto-approval is enabled — [Woobox: Collecting submissions from Instagram](https://help.woobox.com/articles/collecting-submissions-from-instagram/)

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — The explicit "previous 24 hours" lookback plus "throughout the campaign" ongoing collection strongly suggests Woobox is using (or built on top of) the same `ig_hashtag_search`-style Graph API endpoint Meta documents (which itself only returns a limited recent window of hashtag-tagged media, not full historical search), consistent with the organizer needing a Business Profile + Facebook Page — exactly the prerequisite Meta's official hashtag search endpoint requires. This is inferred from the matching account-type and lookback-window pattern, not a vendor statement about which specific endpoint is used.
- No evidence of @mention-based collection was found for Woobox — their documented mechanism is hashtag-only.

### Gaps
- Could not confirm whether Woobox claims use of the "official" Graph API in its own words (no explicit "we use Meta's official API" statement was found, unlike Easypromos), nor any Meta Advanced Access/App Review/verified-partner disclosure.
- Real-time vs. polling cadence beyond the "24 hours" lookback framing was not specified (e.g., how often the feed refreshes after the initial 24-hour window).
- The WebFetch of the primary Woobox help article failed on a TLS certificate error during this session; the content above is a search-result paraphrase of that same page rather than a directly re-verified fetch, and should ideally be re-confirmed if feasible.

## 4. ShortStack — Instagram hashtag/UGC collection for contests/campaigns

### Takeaway
ShortStack explicitly documents that the organizer's Instagram account **must be a Business Account linked to a Facebook Page** before a hashtag feed can be created, and that ShortStack "connects through Facebook to read hashtag posts" — i.e., it is built on the Facebook/Instagram Graph API login flow, not a mention-caption trigger. No @mention-based collection mechanism was found documented for ShortStack; it is hashtag-feed based.

### Cited Findings
- DOCUMENTED FACT (vendor claim) — "You must create an Instagram business account, and the Instagram account must be a Business Account linked to a Facebook Page" before setting up an Instagram hashtag feed — [ShortStack: Creating and Managing an Instagram Hashtag Feed](https://help.shortstackapp.com/hc/en-us/articles/115000264632-Creating-and-Managing-an-Instagram-Hashtag-Feed)
- DOCUMENTED FACT (vendor claim) — "Your Instagram account must be a Business account tied to a Facebook Page you can access, as ShortStack connects through Facebook to read hashtag posts" — [ShortStack: Creating and Managing an Instagram Hashtag Feed](https://help.shortstackapp.com/hc/en-us/articles/115000264632-Creating-and-Managing-an-Instagram-Hashtag-Feed)
- DOCUMENTED FACT (vendor claim) — Required hashtags are entered without the `#` symbol, with multiple hashtags comma-separated — [ShortStack: Creating and Managing an Instagram Hashtag Feed](https://help.shortstackapp.com/hc/en-us/articles/115000264632-Creating-and-Managing-an-Instagram-Hashtag-Feed)
- DOCUMENTED FACT (vendor claim, blog/marketing tier, less technical) — ShortStack "pulls every hashtagged post into one place" and lets you set a date range for the "feed" of hashtagged posts to pull in — [ShortStack blog: How to Collect and Moderate Hashtagged UGC Without a Developer](https://www.shortstack.com/blog/how-to-collect-and-moderate-hashtagged-ugc-posts-without-a-developer/)
- DOCUMENTED FACT (vendor claim, blog) — Setup is described as "a one-time OAuth login, similar to logging into any app," and the feed "monitors your hashtag and pulls in new posts as they come in, typically refreshing every few minutes" — [ShortStack blog: How to Collect and Moderate Hashtagged UGC Without a Developer](https://www.shortstack.com/blog/how-to-collect-and-moderate-hashtagged-ugc-posts-without-a-developer/) — note this specific blog post reads as generic/marketing-level content and does not cite a specific API or access tier; it should be weighted below the help-center article above.
- ShortStack also separately documents "Granting Page permissions using Meta Business Suite," reinforcing that its Instagram integration is routed through a connected Facebook Page's permissions — [ShortStack: Granting Page Permissions Using Meta Business Suite](https://help.shortstackapp.com/hc/en-us/articles/360039066872-Granting-Page-Permissions-Using-Meta-Business-Suite)

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — The explicit "polling every few minutes" framing (from the blog, lower-confidence source) combined with the documented OAuth/Facebook Page login requirement is consistent with ShortStack polling Meta's Graph API (e.g., a hashtag-search-style endpoint) on a short interval under the organizer's own authenticated, Business-linked Instagram account — i.e., a per-customer Facebook Login/Graph-API flow rather than a broad always-on backend scan. This is an inference; ShortStack does not itself publish an architecture diagram.
- No @mention-based ("Mention + Hashtag") combined trigger was found documented for ShortStack, unlike Easypromos; ShortStack's feature is hashtag-only.

### Gaps
- No explicit statement of whether participants need public (vs. can be private) accounts was found in the fetched content, though this is very likely implied (standard for all hashtag-search-based tools, consistent with Meta's API only returning public content) — treat as a probable but not directly confirmed requirement for ShortStack specifically.
- No historical backfill details (e.g., how far back a "feed" can search when first created) beyond "setting the dates you'd like to pull in posts between" were found; this phrasing is ambiguous as to whether backdating actually retrieves older posts or only filters forward from feed creation.
- No mention of Meta Advanced Access, App Review, or verified-partner status was found in ShortStack's own content.

## 5. Gleam — Instagram UGC/hashtag import ("Import" competition actions)

This is one of the clearer pieces of evidence in this research set of a vendor directly attributing a feature/capability change to Instagram API policy changes.

### Cited Findings

Entrants post their submission on their own social media account, along with your specified #hashtags." — [Gleam: Import Entries Into Competitions From External Sources](https://gleam.io/docs/actions/import)

You can even require users to @mention you and use your hashtag" — [Gleam blog: How to Run Instagram Competitions That Actually Work](https://gleam.io/blog/instagram-competitions/)
- DOCUMENTED FACT (vendor claim) — "to use Instagram import methods you must have an Instagram Business Profile" — [Gleam FAQ/docs aggregation, from search synthesis of Gleam's own help pages]
- DOCUMENTED FACT (vendor claim) — "You can import Photos, Videos, or Reels from Instagram posts that @mention your Instagram Business profile, which is now the preferred method over hashtags if you want to see the entrants' username and timestamps" — [Gleam docs/FAQ, per search synthesis]
- DOCUMENTED FACT (vendor claim) — "due to Instagram's new API limitations, Gleam is no longer able to support certain Instagram actions like the 'Like a Photo/Video' action" — [Gleam docs/FAQ, per search synthesis] — this is a direct vendor acknowledgment that a prior Instagram feature was removed specifically because of a Meta/Instagram API policy change, which is useful corroborating evidence (for the broader research question) that these vendors are bound by, and responsive to, Meta's actual API constraints rather than operating outside them entirely.
- To switch to a Business account, Instagram requires connecting to a Facebook Page — [search synthesis of Gleam's own "How Do I Switch to a Business Account on Instagram?" FAQ](https://gleam.io/faq/integrations/social-media-platforms/switch-to-business-account-on-instagram)

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — Gleam's framing that @mention import is "now the preferred method over hashtags" for seeing "entrants' username and timestamps" suggests Gleam may be using a mentions/tagged-media style Graph API endpoint (which, under Meta's API, surfaces richer metadata for an owned Business account's own `mentions` edge) as distinct from the separate, more rate-limited `ig_hashtag_search`-style endpoint for hashtags — consistent with Meta's actual two-track API design (tagged/mentioned media on your own account vs. hashtag search). This is a plausible read of why Gleam's own guidance nudges customers toward mention-based collection, but Gleam does not itself name specific Graph API endpoints publicly.

### Gaps
- Direct WebFetch of Gleam's dedicated FAQ page ("Can I Import Media From Hashtags?") returned HTTP 403 and could not be independently verified beyond the search-engine synthesis; the bullet points above sourced from "search synthesis" should be treated as secondary/lower-confidence citations pending direct page access.
- No statement found on whether Gleam claims "official Meta API" usage in its own words, nor any Advanced Access/App Review/verified-partner disclosure.
- No explicit statement on participant account type (public personal vs. must-be-professional) was found for Gleam.

## 6. Brandwatch — Instagram social listening/UGC monitoring

### Takeaway
Brandwatch explicitly confirms it uses Instagram's **official Graph API** via per-customer OAuth-style account authentication, and explicitly documents a major capability reduction from Instagram's 2018 API policy changes: Brandwatch can still gather all data for a brand's **own connected/owned Instagram channels** and can still run **hashtag searches** ("we are still able to gather all posts for hashtags"), but lost the ability to pull data for **non-owned channels** (e.g., competitor or influencer accounts) entirely, with no expectation that capability returns. This is a case where a vendor is unusually transparent, in its own blog, about a Meta-driven access change — it does not claim any special Advanced Access/elevated-partner status to work around the restriction; it simply documents the restriction as permanent.

### Cited Findings
- DOCUMENTED FACT (vendor claim) — "at Brandwatch we've always asked the users of our platform to authenticate their Instagram account with Brandwatch Analytics" — [Brandwatch: Your Questions Answered: Instagram API Changes](https://www.brandwatch.com/blog/your-questions-answered-instagram-api-changes/)
- DOCUMENTED FACT (vendor claim) — Instagram's April 2018 change reduced rate limits from 5,000 to 200 requests/hour/account; Brandwatch states this change "will not impact your Brandwatch functionality" because it never relied on the higher limit — [Brandwatch: Your Questions Answered: Instagram API Changes](https://www.brandwatch.com/blog/your-questions-answered-instagram-api-changes/)
- DOCUMENTED FACT (vendor claim) — "We can still gather all of your owned posts and associated metrics" and "we are still able to gather all posts for hashtags," but "we are no longer able to receive data" for non-owned channels (competitor/influencer accounts), and Brandwatch does "not expect this functionality to return" — [Brandwatch: Your Questions Answered: Instagram API Changes](https://www.brandwatch.com/blog/your-questions-answered-instagram-api-changes/)
- DOCUMENTED FACT (vendor claim, separate docs) — "Brandwatch users can no longer query or analyze pooled Instagram data collected by other customers and can only see mentions they themselves... have specifically requested," and "for each channel that is connected, a unique access token is created and stored, allowing Brandwatch to access the channel on behalf of users via the network's API" — [search synthesis of Brandwatch help/community docs]
- No mention of Brandwatch claiming Meta Business Partner status, Advanced Access, or App Review in the specific blog post fetched.

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — Brandwatch's documented capability ("still able to gather all posts for hashtags" for channels the customer owns/has connected) reads as consistent with per-customer use of the official Graph API hashtag-search-style endpoint under that customer's own connected, presumably professional, Instagram account — i.e., the same general per-account OAuth pattern as Easypromos/Woobox/ShortStack, rather than Brandwatch operating a privileged, broad cross-account data-access tier. Brandwatch's own text is actually the most explicit rejection, among the products researched, of having any special "listen to anyone's public hashtag/mention activity at scale" capability post-2018 — its enterprise social-listening reputation notwithstanding, its documented Instagram capability is scoped per-connected-account, not an open firehose.

### Gaps
- Could not determine whether Brandwatch's "hashtag search... still works" capability is scoped only to the connected/owned account's own hashtag usage, or whether it can search hashtags across the wider public Instagram corpus (which would require Instagram Public Content Access / Advanced Access akin to Easypromos). The blog text is ambiguous on this distinction.
- The Brandwatch blog post fetched is dated to the original 2018 API change announcement window; no more recent (2024–2026) Brandwatch statement reconfirming or updating this policy was found in this research pass, so current-state accuracy for 2026 cannot be fully confirmed — flagged as a gap.
- No evidence either way on whether Brandwatch holds a formal Meta Business Partner / Marketing Partner badge.

## 7. Other products / cross-cutting observations

### Takeaway
No additional 2026 product beyond the six assigned was identified in this pass as explicitly discussing Meta Advanced Access / App Review as part of its own customer-facing onboarding (Easypromos's "Meta verifies us annually" is the closest such statement found in the entire set). Separately, Meta's own official `ig_hashtag_search` documentation confirms the baseline constraints every one of these vendors is operating within, which is useful context for the report.

### Cited Findings
- DOCUMENTED FACT — Meta's `ig_hashtag_search` Graph API endpoint requires the `Instagram Public Content Access` feature and `instagram_basic` permission, operates only via "Instagram API with Facebook Login," and is capped at 30 unique hashtag queries per rolling 7-day period; it also applies content filtering that returns a generic error for hashtags Meta deems "sensitive or offensive" — [Meta for Developers: ig_hashtag_search reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-hashtag-search)
- Across every vendor in this set that documents its mechanism in any technical depth (Easypromos, Woobox, ShortStack, Gleam, Brandwatch), the consistent, repeated pattern is: **organizer/brand side must have an Instagram professional (Business or Creator) account connected to a Facebook Page**, authenticated via Facebook Login/OAuth into the vendor's app; **participant side can remain an ordinary public personal account** (none of these vendors require participants to have professional accounts — only "must be public" is required). This pattern held across Easypromos, Woobox, and ShortStack's own documentation.
- Only Easypromos's marketing explicitly claims to use "Meta's official API" and claims an annual Meta compliance/legal verification; none of the other five vendors' fetched pages used comparably explicit "official API" language, though Brandwatch's blog implies the same (per-account OAuth to the network's API) without using the phrase "official."
- No vendor in this set (across all fetched pages) displayed a visible "Meta Business Partner" or "Instagram Platform Partner" badge, case study, or App-Review-specific disclosure beyond Easypromos's general "Meta verifies us" claim and the unconfirmed "Meta Verified Tech Provider" search-synthesis mention.

### Inferences
- LIKELY ARCHITECTURE/HYPOTHESIS — Taken together, the evidence across Easypromos, Woobox, ShortStack, Gleam, and Brandwatch is most consistent with a **shared architecture pattern**: each vendor operates its own single Meta app (or small number of apps) that has gone through Meta's App Review for the Instagram Public Content Access / Advanced Access feature set once, at the vendor level — and then each individual organizer/customer performs a Facebook Login + Facebook Page connection that grants that vendor's already-approved app the authorization token needed to call `ig_hashtag_search` / mentions-related endpoints on that organizer's behalf. This explains uniformly across vendors why (a) the *organizer* must have a Business/Creator account + Facebook Page, while (b) *participants* face no such requirement (because Meta's hashtag-search/mentions endpoints only need the querying side, i.e. the organizer, to be an authorized professional account — they return public content from any public account, professional or personal). No vendor in this set publicly confirms this exact framing in those words; it is this researcher's inference from the consistent onboarding pattern plus Meta's own documented endpoint requirements, not a confirmed architectural fact for any specific vendor.
- Direct, un-gated web scraping (bypassing the Graph API entirely) was not found to be documented or claimed by any of the six assigned vendors; it remains a theoretical alternative (and is openly offered by clearly-labeled third-party "scraper" products like Apify's Instagram scrapers, which are a different market category entirely — data-scraping-as-a-service tools, not contest/UGC platforms) but no evidence ties any of the six researched contest/UGC vendors to that approach.
